# F4: legacy 削除(後日・条件付き)

種別: 後続(即時に着手しない) / 依存: F1 + 下記の運用条件

## 目的

v1 変換経路と凍結コピーを削除し、コードベースを v2 単一文法へ完全に収束させる。

## 着手条件(すべて成立してから)

1. ローカルの全 `.nui` ファイルを一度 open + save して v2 化したことをオーナーが
   確認済み(単一ユーザーのローカルツールなので、これが唯一のデータ移行確認)。
   F1 の引き継ぎ欄の記録を参照。
2. その後 1 リリース相当の通常利用で v1 変換が不要だったこと。

条件が成立するまで本タスクは「保留」のまま README に残す。

## 対象範囲

- `src/document/legacyDsl/` ディレクトリ全体とそのテスト。
- `src/document/legacyV1Import.ts` と `documentFile.openDocument` の v1 変換分岐。
- `src/dsl/__fixtures__/sample.v1.nui`。
- `nuiVersion.ts` の意味を「2 のみ受理(>2 と <2 は拒否)」へ簡素化。
- `.nuinui.json` importer は**削除しない**(独立したレガシー入力であり本計画の
  対象外。オーナーが別途不要と判断した場合のみ)。

## 対象外

- 機能変更・文法変更。

## 実装要点

- 削除後、v1 ファイルを開いた場合のエラーメッセージが「未対応バージョン」として
  妥当であること(変換手段が消える旨、旧バージョンのアプリで開けることを案内
  するかはオーナー判断 — 着手時に確認)。

## テスト

- 削除による参照切れゼロ(`npm run build`)。既存全テスト green。
- v1 ファイル open が明確なエラーになることのテスト。

## 受入条件

- `npm test` / `npm run build` / `npm run lint` green。
- `legacyDsl` / `legacyV1Import` / `sample.v1.nui` への参照がリポジトリ内にゼロ
  (docs の履歴的言及を除く)。
