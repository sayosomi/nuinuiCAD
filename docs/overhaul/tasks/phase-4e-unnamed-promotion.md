# Phase 4e: 無名要素の自動昇格(命名+同一Undo行パッチ)

> 親文書: [phase-4-command-line.md](phase-4-command-line.md)。着手前に
> `AGENTS.md` → `docs/overhaul/plan.md` → 親文書 → 4c/4d文書の順で読むこと。

## Context

DSLは無名文を許すが、IDは永続しない(plan.mdの設計判断6)。無名要素への
参照は名前トークンで表現できず、シリアライズすると生IDトークン=再読込で
参照切れになる。そのため4dではコマンドライン候補から無名要素を除外した。
本タスクで「無名要素が参照されたら自動昇格(文脈的な名前を付与し、参照行の
挿入と同一Undoステップでその要素の行もパッチ)」を実装し、除外を解除する。

## Goal

コマンドラインのピックで無名要素を選ぶと、確定時にその要素へ一意な名前が
付き(例: 型別プレフィクス+連番。`makeUniqueElementName` の既存規則に従う)、
新要素の挿入と無名要素の行パッチが**1 Undoステップ**で文書に入る。

## Scope

* 4dで入れたコマンドライン候補の無名除外を解除する。
* セッション引数に「無名要素への参照」を記録できるようにする(充填時は
  実行時IDで保持。命名は確定時まで遅延)。
* 確定処理(4cのconfirm)を拡張:
  1. 引数が参照する無名要素を列挙(直接参照のみ。推移的参照はスコープ外)。
  2. 各無名要素へ `makeUniqueElementName`(名前空間対応)で命名した
     elements配列を作る。
  3. 命名済みelements+新要素挿入を**1回の `commitDocumentChange`** で
     コミットする(ブリッジが変更された文だけを行スプライスし、1 Undo
     ステップに同梱する)。
* 昇格した要素名は、新要素の参照式(アンカー・線ID・数値参照式)に正しく
  反映される(emitは実行時IDベースなので、シリアライズ時に名前トークンへ
  解決されることをテストで確認)。
* バー表示: 無名候補は表示名(`elementNames` の既存の無名表示規則)で
  提示する。昇格予定の名前をピック時点でプレビュー表示する必要はない
  (確定時に決まる)。

## Out of Scope

* 推移的な昇格(無名要素が別の無名要素を参照しているケースの連鎖命名)。
  直接参照された要素のみ昇格する。連鎖が必要になったら別タスク。
* DSLタイプ・通常pick経路(Inspector等)での無名参照の扱い変更。既存経路は
  従来どおり(生IDトークン+明示的な依存エラー)。
* ゴーストプレビュー(4f)・cutover(4g)。

## Existing APIs / files to reuse

* `src/model/elementNames.ts` — `makeUniqueElementName` / 名前空間スコープ・
  無名要素の表示名規則。
* `src/state/cadDocumentStore.ts` `commitDocumentChange` — 複数文変更の
  同一Undoステップ化はブリッジの既存保証。**新しいUndo機構を作らない**。
* `src/dsl/dslSerializer.ts` — 名前トークン解決(昇格後は名前が出る)。
* 4b/4cのセッション確定経路。

## Invariants

* 1作成=1 Undoステップ(昇格パッチ含む)。Undo1回で「挿入行が消え、
  昇格した名前も元(無名)に戻る」こと。
* 昇格は**参照された要素だけ**。無関係な無名要素に触れない。
  コメント・空行・他の行は不変。
* 命名は決定的(同じ文書状態なら同じ名前)。ID生成器と同様、非決定性を
  持ち込まない。
* 消えた参照の暗黙修復をしない: 昇格対象がコミット直前に存在しない
  (staleセッション)場合は明示エラーでキャンセル(4bの方針)。

## Edge cases

* 同一セッションで同じ無名要素を2ステップから参照 → 命名は1回、両参照が
  同じ名前を指す。
* 複数の無名要素を同時昇格 → 連番が衝突しない。
* グループ内の無名要素 → そのスコープで一意な名前+新要素からの参照が
  修飾名で正しく出る。
* 昇格候補と同名の要素をユーザーがセッション中に作った場合はstale
  キャンセルで守られる(外部コミット)。
* forGroup生成要素(`generatedElementIdForTargetForGroup` で正規化された
  参照)の元テンプレート要素が無名の場合も昇格対象。

## Tests

* ピック→確定で昇格: 文書テキストに「無名行へ名前が付いた行パッチ」と
  「名前で参照する新要素行」が同時に現れ、Undo1回で両方戻る。
* 同一要素の複数参照・複数要素の同時昇格・グループスコープの各ケース。
* 昇格後の再読込(テキスト→parse→compile)で参照が解決される
  (生IDトークンが残らない)ことのラウンドトリップテスト。
* 無名候補がコマンドライン候補に(4dの除外解除後)表示されること。
* 既存経路(Inspector pick等)の無名扱いが変わっていないこと。

## Manual verification

* 実アプリ: DSLに無名点を直接タイプ→コマンドラインで線作成→無名点を
  ピック→確定。エディタ上で無名点の行に名前が付き、Undo1回で両方戻る。
  保存→再起動→読込で参照が生きている。

## Completion criteria

* 無名要素をピックした作成フローが「命名+参照+1 Undo+永続往復」を満たす。
* `npm test` / `npm run build` / `npm run lint` green。
