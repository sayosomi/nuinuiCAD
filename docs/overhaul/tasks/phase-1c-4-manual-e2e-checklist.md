# Phase 1c-4 完了ゲート: 手動E2Eチェックリスト(最小版)

> 前提文書: `phase-1c-4-selection-ui-store.md`(実装タスク本体、末尾に14項目の
> 網羅版チェックリストあり)。本書はその**最小サブセット**を、Phase 1d 着手前の
> ゲートとして人間が実施できる独立した手順書にしたものです。網羅版と矛盾する
> 記述はなく、実施順序と具体的な操作手順を補っています。

## 対象と目的

Phase 1c-4 で selection(`selectedElementId` / `selectedElementIds` /
`selectionAnchorElementId` / `selectedParameterKey`)を文書ストア
(`cadDocumentStore`)から UI ストア(`cadUiStore`)へ移動しました。
本チェックリストは、この移動が実際の Tauri デスクトップアプリ上で以下を
壊していないことを確認するためのものです。

* 文書(図形・パラメータ)の Undo/Redo 履歴と、selection の復元が正しく連動する
* selection の変更単独では文書 Undo 履歴が増えない
* ドラッグ中の selection・プレビュー挙動が変わっていない
* fatal な DSL 編集時に文書が失われない
* dangling 参照が warning として扱われ、文書全体が壊れない
* 保存 JSON に UI ストアの状態(viewport・ダイアログ開閉フラグ・fold 状態等)が
  漏れていない(実装中に一度この漏れを検出し修正済みのため、実機での最終確認が
  特に重要)

## 前提条件

1. `npm run desktop:dev` (または相当のコマンド) で Tauri デスクトップ版を
   dev ビルドで起動する。ブラウザ版(Vite dev server 単体)ではなく、
   Tauri デスクトップアプリで実施すること(AGENTS.md: Tauri が唯一の
   維持対象プロダクト)。
2. DevTools コンソールを開いておく。macOS + Tauri v2(WKWebView)では以下の
   いずれかの方法で開ける:
   * **右クリックで開く(まずこちらを試す)**: アプリのウィンドウ内で右クリック
     し、「Inspect Element」を選ぶ。dev ビルドではデフォルトで有効。
   * **Safari の Web Inspector 経由(右クリックに出ない場合)**: Safari の
     `設定 > 詳細` で「メニューバーに"開発"メニューを表示」をオンにし、
     アプリを起動したまま Safari の `開発 > <Macの名前>` サブメニューから
     nuinuiCAD のWebViewを選んで Web Inspector を開く。
   これで Console タブを開いておき、**全項目共通の確認**として、
   以下がコンソールに出ないことを都度確認する:
   * `[shadowText]` から始まる警告
   * 影テキスト等価性 assert の失敗ログ
   * reconcile(ID照合)警告
   * 未捕捉の例外・React エラーオーバーレイ

   (要素の依存エラーなど、通常の warning 診断バッジの表示は対象外。
   これはアプリの正常機能であり、コンソールエラーではない。)
3. 各シナリオの前に「新規作成」でクリーンな文書から始めるか、直前のシナリオの
   状態が次のシナリオに影響しないことを確認してから進める。
4. 実施結果は本書末尾の記録表に ✅ / ❌ と気づいた点を書き込む。

## シナリオ 1: 選択と Undo/Redo の連動

**手順**

1. 新規作成、または既存図形がある文書を開く。図形リスト(左パネル)から
   点 A を選択する。
2. 右パネルでパラメーター編集モード(`e` または `Enter`)に入り、点 A の
   x または y 座標を変更して確定する(Canvas 上のドラッグではなく、
   パラメーター編集で移動させる。ドラッグ経由の確認はシナリオ3で別途行う)。
3. 図形リストから点 B(A とは別の要素)を選択する。
4. `Mod+Z`(Undo)を1回押す。
5. `Mod+Y`(Redo)を1回押す。

**期待結果**

* 手順4の Undo後: 点Aの座標が移動前の値に戻る。
* 手順4の Undo後: 選択が「点Aへの座標変更を行った直後の選択状態」——
  すなわち点Aが選択された状態——に戻る(点Bのままにはならない)。
* 手順5の Redo後: 点Aの座標が移動後の値に戻る。
* 手順5の Redo後: 選択が手順3で選んだ点Bに戻る。
* 各操作でコンソールに warning/assert/例外が出ない。

## シナリオ 2: 選択だけの変更は文書 Undo を増やさない

**手順**

1. 現在の Undo 履歴段数を把握する(コマンドパレットや UI に履歴段数の表示が
   なければ、この後の Undo が「何も起きない/直前の図形操作まで戻る」ことで
   間接的に確認する)。
2. 点Aを選択する。
3. 点Bを選択する(図形は一切変更しない)。
4. `Mod+Z`(Undo)を1回押す。

**期待結果**

* 手順2・3の選択変更で、図形やパラメータには一切変化がない。
* 手順4の Undo が「選択をBからAに戻す」動作にはならない
  (selection 変更は文書履歴に乗らないため、Undo は選択変更より前の
  直近の**文書**操作まで一気に戻る、または直前に文書操作がなければ
  「これ以上戻れない」状態のまま何も起きない)。
* コンソールに warning/assert/例外が出ない。

## シナリオ 3: Canvas ドラッグ中のプレビューと確定

**手順**

1. 点(または線の端点)をクリックして選択する。
2. マウスボタンを押したままドラッグし、離す前に一旦動きを止めて Canvas の
   表示を確認する(mouse up はまだしない)。
3. さらにドラッグを続けてから mouse up で確定する。
4. `Mod+Z`(Undo)を1回押す。

**期待結果**

* 手順2: ドラッグ中は Canvas 上の表示だけがリアルタイムに追従し、
  この時点ではまだ Undo 履歴は増えない。
* 手順3の確定で、Undo 履歴がちょうど1件だけ増える(ドラッグ中の中間位置が
  複数の履歴エントリとして残らない)。
* 手順4の Undo で、ドラッグ開始前の元の位置に一度で戻る。
* 選択していた要素は、ドラッグ確定後も同じ要素が選択されたままである。
* コンソールに warning/assert/例外が出ない。

**補足(ゼロ delta キャンセル、任意)**: ドラッグを開始してから元の位置に
戻して mouse up した場合、Undo 履歴が増えないことも合わせて確認すると良い
(必須ではないが `phase-1c-4` 網羅版チェックリストの項目5に対応)。

## シナリオ 4: fatal な DSL 編集からの回復

DslPanel(`Mod+Shift+D` で開く、または対象要素を選択してから開く)で
一時的に文書全体を「編集中」テキストとして開き、構文を壊せる経路がある場合に
実施する。そのような経路が現状の UI にない場合は、このシナリオは
「対象経路なし」として記録表に注記し、スキップしてよい。

**手順**

1. DslPanel を開き、既存のテキストの一部を意図的に構文エラーになるよう
   編集する(例: 閉じ括弧を消す)。
2. 診断表示(エラーメッセージ)が出ることを確認する。
3. DslPanel を適用せずに Canvas を確認する。
4. DslPanel のテキストを元の正しい構文に戻す(または Undo で復帰させる)。

**期待結果**

* 手順2: fatal な構文エラーが診断として表示される。
* 手順3: Canvas の図形表示は、編集前の最後に成功した(last-good)状態を
  維持しており、消えたり壊れたりしない。
* 手順3: 編集中のテキスト自体は勝手に消えたり巻き戻ったりしない
  (sourceText は編集中の壊れたテキストを保持したまま、doc は last-good を
  保持する設計)。
* 手順4: 構文を直す、または適用前に離脱することで正常状態に復帰する。
* コンソールに、想定内の診断ログ以外の未捕捉例外が出ない。

## シナリオ 5: dangling 参照(warning への降格)

**手順**

1. 他の要素から参照されている要素(例: 別の点のオフセット元になっている点)を
   選択し、削除する。または、参照先要素をリネームして参照が壊れる状態を
   作ってもよい。
2. 参照元の要素に warning 診断(依存エラー表示)が出ることを確認する。
   文書全体は消えず、他の要素は通常どおり表示され続ける。
3. 削除(またはリネーム)した要素を復元する(削除なら Undo、リネームなら
   元の名前に戻す)。
4. warning が消えることを確認する。
5. `Mod+Z` / `Mod+Y` で Undo → Redo を1往復させる。

**期待結果**

* 手順2: 文書全体が `document=null` のような致命的破損にならず、
  参照元要素だけが警告マーカー付きで表示される。
* 手順3〜4: 参照先を復元すると警告が自動的に解消する。
* 手順5: Undo/Redo を往復しても選択・ID が破綻しない
  (ID reconciliation により、rename の場合は同一要素として追跡され続ける)。
* コンソールに warning 診断以外の未捕捉例外が出ない。

## シナリオ 6: 保存 JSON に UI ストア状態が漏れていないこと

このシナリオは**実装中に一度検出・修正した不具合の実機確認**であり、
本チェックリストの中でも優先度が高い。

**手順**

1. 図形を数点作成・選択し、Canvas の pan/zoom を動かし、DslPanel や
   パレット設定ダイアログなど、いずれかの UI パネル/ダイアログを一度
   開閉しておく(UI ストアに非デフォルト値を作っておくため)。
2. グループがあれば、折りたたみ(fold)状態を一度トグルしておく。
3. `Mod+S`(保存)で `.nuinui.json` として保存する。
4. 保存されたファイルをテキストエディタで開き、内容を確認する。
5. アプリを再読込(または「開く」で同じファイルを再読込)する。

**期待結果**

* 保存された JSON の `document` オブジェクトに、以下が**含まれていない**こと:
  * Canvas / 印刷プレビューの viewport(pan/zoom)
  * 各種ダイアログ・パネルの開閉フラグ(`showDslPanel` 等)
  * グループの折りたたみ状態(fold state。Phase 1c-1 で文書モデルから
    UI ストアへ移した対象)
  * pick モード・依存ジャンプモードなどの一時 UI 状態
* JSON に含まれてよいのは、`selectedElementId` /
  `selectedElementIds` / `selectionAnchorElementId` /
  `selectedParameterKey` の4フィールドのみ(形式互換のため当面残置。
  Phase 1d で除去予定)。
* 再読込後、図形・パラメータ・selection が保存前と意味的に同一であること。
* コンソールに warning/assert/例外が出ない。
